# Integración de escritorio: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ejecutar la interfaz existente en Tauri, con Django administrado y datos persistentes, dejando el instalador para el final.

**Architecture:** Rust administra un proceso Python local, sus datos y su credencial por apertura. React consulta un comando limitado de estado antes de montar la aplicación existente. Se mantiene el modo navegador.

**Tech Stack:** Tauri 2, Rust, React, TypeScript, Django y Waitress existentes.

**Spec:** `docs/superpowers/specs/2026-11-05-desktop-design.md` (aprobada en la conversación).

## Global Constraints

- Windows; ventana inicial de 1280 × 800 y mínimo de 900 × 560.
- API exclusivamente en `127.0.0.1`; credenciales solo en memoria.
- Datos fuera del código y sin reemplazo silencioso de una base desaparecida.
- Sin instalador ni PyInstaller en esta fase; sin cambios al contrato del backend.

## Review Focus

- Carpeta o base desaparecida tras el primer uso: rechazar sin crear una base nueva (tarea 1).
- Python falla o se agota el plazo: error visible y limpieza del proceso (tarea 1).
- Cierre durante el arranque: no dejar procesos huérfanos (tarea 1).
- API consultada antes de recibir credencial: impedir montar App (tarea 2).
- Reintento de interfaz: consultar estado sin iniciar más procesos (tarea 2).

### Resultado de la ejecución

- Tareas 1, 2 y 3 completadas. Se usaron permisos autogenerados por `AppManifest::commands`, en lugar del archivo manual `permissions/desktop.toml` propuesto: mismo comando limitado y una sola fuente de declaración.
- Se instalaron con aprobación Rust y las herramientas C++ de Windows; se creó `backend/.venv` con los requisitos existentes. No se modificó código ni contrato del backend.
- Base inicial del frontend: 257 pruebas correctas. Resultado final: 262 pruebas correctas, lint y build correctos.
- Rust: 13 pruebas correctas, `cargo check` y `cargo fmt --check` correctos. La integración real prueba persistencia del dueño ficticio, credencial renovada y sesión anterior invalidada en carpetas temporales.
- Revisión independiente: se corrigió una carrera de Windows creando Python suspendido y asignando el Job antes de reanudar el hilo. La regresión falló antes y pasó después; el revisor confirmó la corrección sin otros problemas importantes.
- Comprobación nativa de Windows: pantalla «Iniciar sesión» visible en Tauri, conectada a Django. Segunda apertura: sale el proceso secundario y queda una sola instancia. Cierre normal desde el botón de la ventana: cero procesos desktop y cero listeners del backend y de Vite.
- Se dejó la aplicación cerrada tras la comprobación. No se crearon cuentas de prueba en los datos del usuario ni se modificaron sus credenciales.
- Pendiente para distribución: empaquetado Python, instalador, respaldo previo a migraciones/actualizaciones y prueba de actualización de una versión anterior. La actualización automática no está implementada.
- Sin commits ni cambios de rama: `.git` es de solo lectura en esta sesión.
